## Ownership, hold and cancellation

The copied bridge retains source/compile guards, hidden bounded launch, exclusive
lease claim, PID/executable/birth/parsed argv identity, bounded child logs, one original
CloseMainWindow path and verified exit/release receipts. No force termination,
force release, takeover, retry or new process manager is added.

Hold is checked before admission, at atomic claim, in both owned loops, immediately
before the sole existing normal-close call and during atomic release. Additional
checks immediately before launch and at atomic attachment prevent a hold arriving
after claim from being overwritten by a running status. Such failure preserves the
claim/session for the coordinator; attachment receipt records any already started
PID. This source change has not been exercised natively.

If hold arrives during an active owned run, report its recorded PID/status, stop
follow-ons and preserve it. No GUI termination or cooperative cancel-close is issued
under hold. A later cleared hold never causes automatic resume. The wrapper cannot
pause world scripts already loaded; this autonomous source may complete its bounded
startup phase independently, but the held run remains censored.

When hold is inactive, REFORGER_QA_CANCEL_PATH is checked prelaunch and in both owned
loops. Cancellation uses the same guarded normal-close branch only. A canceled,
deadline, overflow or uncertain run cannot become PASS from late markers. Closure
uncertainty preserves ownership and prevents following cases. Lifecycle PASS requires
matching owner/argv/lease receipts, verified exit and released lease, never exit code
alone. Secrets from owner-private receipts are not emitted as evidence.
